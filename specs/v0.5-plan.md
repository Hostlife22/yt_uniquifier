# yt-uniquifier v0.5 — Modern PyQt6 desktop UI

> Roadmap для полного rewrite GUI shell. От минимального single-window
> file picker (текущий `gui/app_pyqt.py`, 260 строк, 1 из 10 CLI команд)
> к многоэкранному desktop-приложению с **полным покрытием 10 CLI
> команд + v0.4.1 validation harness + inline profile editor + embedded
> QA HTML viewer**.
>
> Стек тот же: PyQt6 + `QWebEngineView` для QA viewer. Никаких
> web/Electron/Tauri toolchain'ов. Каждый release ([21–25]) shippable
> независимо.

---

## Context

После v0.4 CLI покрывает 10 команд (run / batch / calibrate / qa / corpus
/ queue / worker / probe / preflight / version) + manual validation
harness через `tools/`. PyQt6 GUI остался на v0.1 уровне:

- file pickers для input/output
- profile dropdown (просто сканирует `profiles/*.yaml`)
- encoder dropdown
- Run button + progress bar + log

Не покрыто **9 из 10 CLI flows**: batch, calibrate, qa standalone,
corpus, queue/worker, validation, profile editing, probe inspection,
preflight как pre-run step.

Архитектура core нас не подведёт: `orchestrator.run_full(plan, options,
on_event, cancel_token)` — единственная entry для encoding; `Corpus`,
`FileQueue`, `calibrate` — у всех clean event-driven API. Worker
pattern (QThread + pyqtSignal) уже доказан в `gui/worker.py`.
Расширяем его на 8 новых workers — по одному на long-running операцию.

**Зачем v0.5 а не сразу полировать CLI:** CLI отлично работает для
power users, но для adoption нужен desktop entry point. Profile editor
inline + queue dashboard + validation wizard сильно снижают барьер для
non-CLI пользователей.

## Архитектура (краткая выжимка)

```
gui/
├── app_pyqt.py             # rewrite — MainWindow + sidebar nav
├── state.py                # AppState — single source of truth
├── theme.py                # QSS dark/light tokens
├── screens/                # 10 экранов (по одному на CLI flow + Editor + History + Settings)
├── widgets/                # 8 reusable (FilePickerRow, EncoderSelector, …)
└── workers/                # 9 QThread-based (RunWorker, BatchWorker, …)
```

**Navigation:** `QListWidget` sidebar + `QStackedWidget` content area
(аналог Slack/Discord/VSCode).

**State management:** `AppState` хранит текущие selections, recent files,
run history. Persisted в `~/.config/yt_uniquifier/state.json` +
`history.json`. Screens подписываются на изменения через Qt signals.

**Worker contract:** все workers наследуют `WorkerBase(QThread)`:

```python
class WorkerBase(QThread):
    started_ = pyqtSignal()
    finished_ok = pyqtSignal(object)
    failed = pyqtSignal(str)
    log = pyqtSignal(str)
    progress = pyqtSignal(float, str)

    def request_cancel(self) -> None:
        self.cancel_token.cancel()
```

Конкретные workers добавляют свои signals (`CalibrateWorker.step(dict)`,
`BatchWorker.file_done(str)`, etc.).

См. [мастер-план в plan-файле](/Users/admin/.claude/plans/snoopy-sprouting-kay.md)
для полной структуры файлов и per-screen specifications.

## Новые dependencies

```toml
[project.optional-dependencies]
gui = [
    "PyQt6~=6.7",
    "PyQt6-WebEngine~=6.7",   # NEW — embedded QA HTML viewer
]
gui-charts = ["PyQt6-Charts~=6.7"]  # NEW optional — calibrate convergence chart
dev = [
    # existing +
    "pytest-qt~=4.4",         # NEW — PyQt6 widget testing fixtures
]
```

`PyQt6-WebEngine` — ~150 MB. Сделать graceful-fallback в QA Viewer
(если import fails → кнопка "Open in browser" вместо embedded view),
чтобы пользователи могли поставить `[gui]` без WebEngine.

`PyQt6-Charts` опционален: `ChartWidget` имеет QPainter fallback.

## Что **НЕ** делаем в v0.5

Discredited / out-of-scope:

- **Web/Electron/Tauri shell** — пользователь выбрал PyQt6 explicitly.
- **Mobile / web hosting** — desktop-only tool.
- **Multi-user, auth, cloud sync** — single-user local.
- **Real-time CID API integration** — нет API; Validation wizard остаётся manual record loop.
- **Automated YouTube upload** — TOS-risky.
- **Plugin system для custom transforms** — transforms self-register через `core/transforms/`, GUI подхватывает автоматически без plugin machinery.
- **Drag-drop reorder transforms в Profile Editor** — порядок задан pipeline-ом, не редактируется в YAML.
- **Live preview encoded segment** — слишком тяжело; пользователь смотрит финальный output.
- **In-app video player** — `webbrowser.open()` достаточно.

## Risks & mitigations (summary)

| Risk | Mitigation |
|---|---|
| `PyQt6-WebEngine` heavy dep | Graceful fallback на "Open in browser" |
| Cross-platform QSS quirks | Test на 3 OS перед v0.5.4 |
| GUI thread blocked sync ops | Всё non-trivial через `WorkerBase` |
| Inline profile editor corrupts YAML | Pydantic validation + `.yaml.bak` backup |
| 25+ новых файлов разрастаются | Strict screens/widgets/workers separation |
| Worker cancel оставляет orphan ffmpeg | Existing `_terminate(proc)` в `runner.py` handles |
| QWebEngineView не рендерит styled HTML | Test early в Phase 3; fallback на browser |
| PyInstaller cross-compile сложен | Phase 5 опция: `pipx install` walkthrough если PyInstaller провалится |

## Source citations

- Sidebar navigation pattern: Slack / Discord / VSCode (industry standard для 10+ screens).
- `WorkerBase` pattern: extends existing `gui/worker.py:Worker` (proven in v0.1).
- `QWebEngineView` для embedded HTML: Qt docs + standard для embedded reports.

## Exit criteria для v0.5.4

После Phase 5 ship'a:

- Все 10 CLI команд имеют GUI equivalent (либо native screen, либо wizard).
- `yt-uniq-gui` запускается на macOS / Linux / Windows без user-side ffmpeg dance.
- `docs/gui.md` покрывает каждый screen с screenshots + keyboard shortcuts.
- PyInstaller spec собирает single-binary для каждой OS (или fallback на pipx с clear instructions).
- README updated с GUI section.
- Все v0.4.x core тесты + ~40 новых GUI тестов проходят.
- `ruff check . && mypy src/yt_uniquifier` clean.

Дальше (v0.6+) — фокус на real-CID validation data (ждём 30+ samples
через wizard) и потенциально neural FP attack mode если данные покажут
что классические transforms недостаточны.
