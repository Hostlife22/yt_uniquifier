## Context

Cross-referencing two independent research reports against the v0.3.1
implementation surfaced one **critical doctored hole** and four **measurable
gaps** that are explicitly absent from our pipeline but present in published
academic literature 2010–2025.

### The critical hole

Our `cid_aware.yaml` profile ships with `audio.pitch_tempo.pitch = 1.04` (a
+4% shift). Scott Smitelli's 2010 controlled experiment against YouTube
Content ID established:

| Pitch shift | CID match outcome |
|---|---|
| `≤ ±5%` | matches (we lose) |
| `≥ ±6%` | does not match (we win) |

Our default `+4%` is **inside the match zone** by a comfortable margin. This
is the single most consequential finding of the research: our shipped
default is theoretically guaranteed to be matched by the CID rules verified
by Smitelli. Fix: change one YAML literal (1.04 → 1.06).

### Verified gaps

| Gap | Source | Effect |
|---|---|---|
| Random temporal frame jitter (1/10 blackout / dup / drop) | Fojcik & Syga, arXiv:2501.11171 (2025) | 60%+ μAP drop in Meta VSC2022 baseline |
| Audio FP Hamming delta as explicit metric | Smitelli 2010 — audio is the most predictive channel | We compute chromaprint but don't expose distance as KPI |
| Per-segment seed divergence | Fojcik 2025 + temporal-attack literature | One seed per run leaves adjacent segments close enough for partial matches |
| Haas stereo delay (mono-compatible) | Smitelli 2010 — phase inversion breaks CID; Haas is its perceptually-clean cousin | Stereo manipulation absent from pipeline |
| Parametric noise overlay 20–30% | Smitelli 2010 — `≥45%` white noise breaks CID; lower mix shifts chromaprint without harming intelligibility | We have `video.noise` but no audio noise overlay |

## Source citations (verifiable)

All sources are publicly accessible. Cite these in `docs/profiles.md` and
QA report tooltips so the parameter choices are inspectable.

| Source | Used for |
|---|---|
| Scott Smitelli, "Fun with YouTube's Audio Content ID System" (2010). https://www.scottsmitelli.com/articles/youtube-audio-content-id/ | Pitch ±5/6% threshold; noise ≥45% threshold; phase manipulation breaks audio CID |
| Fojcik & Syga, "Counteracting Temporal Attacks in Video Copy Detection", arXiv:2501.11171 (2025) | Random frame blackout (p=1/10) and speed jitter drop μAP 60%+ on Meta VSC2022 baseline |
| Saadatpanah, Shafahi, Goldstein, "Adversarial Attacks on Copyright Detection Systems", ICML 2020 (arXiv:1906.07153) | Demonstrated that audio fingerprint matching (Shazam-class) is gradient-attackable; supports treating audio FP as primary KPI |
| Singh et al., "Robust Neural Audio Fingerprinting using Music Foundation Models", arXiv:2511.05399 (NeurIPS 2025) | Defensive paper signalling that platforms are moving to neural FP; reinforces need for stronger pitch shift + spectral changes |
| Zhang et al., "AttkScopes", USENIX Security 2025 | Cited as out-of-scope: white-box adversarial requires API; we don't have CID API |

## What this roadmap does **not** include — discredited by research

Both reports agree these have no doctored basis or are infeasible offline:

- **Watermark / PNG overlay** — UX hit; doesn't move perceptual hashes.
- **Adversarial gradient attacks on CID** — requires CID API; ~8M queries
  per arxiv attack papers; impossible black-box.
- **`-map_metadata -1`** as a primary technique — file-hash level, not
  perceptual.
- **GOP / PTS / DTS jitter** — same: file-hash, not perceptual.
- **Reverse audio** — Smitelli says it passes CID; 100% breaks UX. Not
  uniquification, that's destruction.
- **First-30s skip** — that's editing, not a transform.
- **AB-style 60/120/240fps frame interleaving** — platform transcoding
  collapses the inserted frames; audio still matches; file size 2-4×.
- **Face morphing / deepfake** — out of scope, legal/ethical risk.
- **Mobile-app "anti-CID" features (CapCut, InShot, VEED)** — verified
  myth; no such features exist in public products.

## What we'll know after v0.3.3 ships

The combination of pitch ≥ 6% (above Smitelli threshold) + frame-level
temporal jitter (Fojcik verified) + audio Hamming delta visible in QA
+ divergent per-segment seeds + parametric noise overlay covers **every
verified gap in the public literature** that's reachable through pure
ffmpeg filters and YAML configuration.

What remains after v0.3.3 is either:

1. **Real-CID validation** (unlisted-upload harness): tells us empirically
   if the layered defaults actually pass real CID. This is the next step
   that can't be replaced with more transforms.
2. **ML-based attacks** (differentiable Chromaprint / diffusion-noise): a
   1-2 month research project, deferred to v0.4+ if v0.3.3 metrics show we
   still need more.

If v0.3.3's KPIs hit their targets and a single real-upload test confirms
no-match against the user's own corpus, we declare the public-OSS frontier
reached.
